# New Map Autoclear 개발 계획

## 목표와 전제

매크로가 없는 처음 보는 Geometry Dash 레벨에서 프로그램이 입력을 직접 찾고, 찾은 입력으로 레벨을 다시 재생해 클리어합니다.

첫 버전은 다음 조건만 지원합니다.

- Classic Normal 모드
- 플레이어 1명
- 기본 큐브와 정적인 블록·가시
- 레벨 시작 지점부터 플레이
- 실패하면 자동으로 처음부터 다시 시도
- 짧은 로컬 테스트 레벨

처음부터 모든 게임 모드와 온라인 레벨을 지원하지 않습니다. 비행선, 웨이브, 볼, 로봇, 스파이더, 듀얼, 포탈, 오브, 이동 오브젝트와 랜덤 트리거는 기본 큐브가 안정된 뒤 각각 추가합니다.

## 선택한 방법

초기 버전은 게임 물리를 밖에서 완전히 흉내 내지 않습니다. Geometry Dash 자체를 정확한 실험기로 사용합니다.

1. Geode 모드가 주변 장애물과 플레이어 상태를 읽습니다.
2. 점프를 누를 프레임과 뗄 프레임 후보를 만듭니다.
3. 후보를 실제 게임에서 실행합니다.
4. 죽은 위치와 가장 멀리 간 위치를 기록합니다.
5. 더 멀리 간 입력을 남기고 그 다음 구간을 탐색합니다.
6. 끝까지 간 입력을 저장하고 처음부터 다시 재생해 검증합니다.

이 방법은 시도 횟수가 필요하지만 게임과 다른 가짜 물리를 만드는 위험이 적습니다. 화면 인식은 내부 정보로 해결할 수 없는 경우에만 나중에 검토합니다.

## 프로그램 구성

```text
new-map-autoclear/
├── CMakeLists.txt
├── mod.json
├── README.md
├── PLAN.md
├── src/
│   ├── main.cpp          # 메뉴, 시작, 중지, 상태 표시
│   ├── Telemetry.*       # 플레이어와 주변 오브젝트 읽기
│   ├── EpisodeRunner.*   # 입력 실행, 사망, 재시작 관리
│   ├── Solver.*          # 다음 입력 후보 생성과 선택
│   └── Solution.*        # 성공한 입력 저장과 불러오기
└── tests/
    ├── SolverTests.cpp
    └── SolutionTests.cpp
```

자동 클리어 프로그램과 기존 `macro-replay`는 독립적으로 빌드합니다. 자동 클리어가 성공한 입력은 나중에 GDR 파일로 내보내 기존 Target Replay에서도 재생할 수 있게 합니다.

## 단계별 구현과 합격 조건

### 1단계: 관찰기

Geode 메뉴에 `New Map Autoclear` 버튼을 추가하고 다음 정보를 로그에 기록합니다.

- 현재 물리 프레임과 진행률
- 플레이어의 위치, 속도, 중력 방향과 바닥 접촉 여부
- 플레이어 앞쪽 일정 거리 안의 오브젝트 ID, 종류와 충돌 사각형

합격 조건:

- 짧은 테스트 레벨에서 블록과 가시의 위치가 화면과 맞습니다.
- 같은 레벨을 세 번 재시작했을 때 정적인 오브젝트 정보가 같습니다.
- 관찰 기능만 켜도 게임 플레이가 달라지지 않습니다.

### 2단계: 입력 실행기

프레임별 누르기·떼기 목록을 실행하고, 사망 또는 완료를 감지해 자동으로 재시작합니다. 매 시도마다 입력, 사망 프레임, 최대 진행 위치를 저장합니다.

합격 조건:

- 같은 입력을 다섯 번 실행했을 때 같은 위치까지 갑니다.
- `Stop`을 누르면 입력을 모두 놓고 즉시 수동 조작으로 돌아갑니다.
- 시도 횟수와 최고 진행률이 게임 화면에 표시됩니다.

### 3단계: 기본 큐브 탐색기

아무 입력 없이 진행하다가 죽은 지점 앞에서 점프 시작 프레임과 유지 시간을 여러 개 시험합니다. 더 멀리 간 후보를 선택하고 이미 통과한 입력 앞부분은 고정합니다.

처음에는 탐색 범위를 작게 제한합니다.

- 버튼 1만 사용
- 점프 시작 시점과 누르는 길이만 변경
- 한 번에 가까운 장애물 한 구간만 해결
- 시도 횟수와 전체 탐색 시간에 상한 설정

합격 조건:

- 평지, 가시 1개, 가시 3개, 간단한 계단으로 만든 테스트 레벨을 사람 입력 없이 해결합니다.
- 해결하지 못하면 무한 반복하지 않고 이유와 최고 진행률을 표시합니다.

### 4단계: 해답 검증과 저장

탐색을 멈춘 뒤 성공한 입력만 사용해 처음부터 다시 실행합니다. 연속 재생에 성공하면 해답으로 저장합니다.

합격 조건:

- 같은 해답으로 다섯 번 연속 완주합니다.
- 레벨 ID와 레벨 내용 확인값이 다르면 오래된 해답을 실행하지 않습니다.
- GDR 내보내기 결과를 Target Replay가 읽을 수 있습니다.

### 5단계: 지원 범위 확장

기본 큐브가 안정된 뒤 한 기능씩 추가하고 각 기능마다 전용 테스트 레벨을 만듭니다.

1. 속도·중력·크기 포탈
2. 점프 패드와 오브
3. 볼과 로봇
4. 비행선과 UFO
5. 웨이브와 스파이더
6. 듀얼과 움직이는 장애물

각 게임 모드는 조작 규칙이 다르므로 하나의 탐색 규칙에 억지로 섞지 않고 별도 전략으로 추가합니다.

## 테스트 레벨

개발용 로컬 레벨을 작은 기능별로 만듭니다.

- `00-flat`: 입력 없이 완주
- `01-one-spike`: 점프 한 번
- `02-three-spikes`: 긴 점프
- `03-two-jumps`: 두 구간 입력 연결
- `04-platforms`: 높이가 다른 바닥
- `05-hold-length`: 누르는 길이가 중요한 구간

각 레벨은 짧고 장식이나 랜덤 요소가 없어야 합니다. 복잡한 실제 레벨은 이 여섯 테스트가 모두 통과한 뒤 사용합니다.

## 중단 조건과 표시할 오류

다음 상황에서는 자동으로 멈추고 사용자가 이해할 수 있는 메시지를 표시합니다.

- 아직 지원하지 않는 게임 모드나 오브젝트 발견
- 정해진 최대 시도 횟수 초과
- 같은 입력의 결과가 반복 실행마다 크게 달라짐
- 레벨이 바뀌거나 사용자가 직접 입력함
- 게임 일시정지 또는 모드 종료

## 구현 순서

바로 구현할 범위는 1단계 관찰기입니다. 관찰 결과가 정확한지 실제 게임에서 확인한 뒤에만 2단계 입력 실행기를 만듭니다. 각 단계는 빌드 성공, 자동 테스트, 짧은 실제 레벨 테스트를 모두 통과해야 다음 단계로 넘어갑니다.
